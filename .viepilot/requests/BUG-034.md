# BUG: Voice UI callbacks can race attribute restoration and destroyed views

## Summary

Conversation and Walkie register their service callback before the asynchronous attributes reply initializes `MessagesAdapter`. A real service message can therefore reach `VoiceTranslationFragment.onMessage()` while `mAdapter` is null. The attributes listener also remains queued after service disconnect and can update stale view references after `onStop()`/view teardown.

## Evidence

- `CustomServiceConnection.onServiceConnected()` registers `VoiceTranslationServiceCallback` before invoking the fragment's `onServiceCommunicator()` callback.
- The fragment then calls `restoreAttributesFromService()`, and only its later `ON_ATTRIBUTES` reply constructs `mAdapter`.
- `VoiceTranslationFragment.VoiceTranslationServiceCallback.onMessage()` dereferences `mAdapter`, `smoothScroller`, and the RecyclerView/layout manager without checking initialization or the view lifecycle.
- `CustomServiceConnection.disconnectCommunication()` removes the main callback, but `VoiceTranslationServiceCommunicator.attributesListeners` is not cleared and already queued Handler messages are not cancelled or generation-gated.

A fast peer message, recognition callback, or late attributes reply during enter/leave/recreate can therefore cause a main-thread `NullPointerException`, mutate a detached view, or replay stale state into a new fragment instance.

## Acceptance criteria

- [ ] The RecyclerView adapter exists synchronously before any service callback can be delivered, or messages are buffered behind an explicit initialized state.
- [ ] Attribute and event callbacks are scoped to a view-generation token and only render while the current view lifecycle is at least STARTED.
- [ ] Disconnect/onDestroyView clears pending attribute listeners and suppresses already queued callbacks from the old connection.
- [ ] Callback rendering is null-safe and cannot call a stale RecyclerView/layout manager/Activity.
- [ ] Deterministic tests deliver message-before-attributes, attributes-after-stop, and old-generation callbacks after recreation for both modes.
