# 🔧 ENHANCEMENT: Add executable APK qualification for voice-service crash regressions

## Meta
- **ID**: ENH-013
- **Type**: Enhancement
- **Status**: new
- **Created**: 2026-09-19
- **Breaking**: No

## Summary
The original near-zero coverage finding is obsolete: the project now has 189 JVM tests and 24 API 36 instrumentation tests. The remaining release-risk gap is that the tests which guard voice-service permissions and foreground startup are largely source-text/unit assertions or fake-controller smoke tests; they do not execute the installed APK through the failure routes that have repeatedly crashed physical phones.

## Current Feature
N/A — this is about the absence of a safety net for all existing features.

## Current Behavior
`VoiceServiceLaunchPolicyTest` proves ordering by searching Java source strings. `OnDeviceModeInstrumentedTest` validates controller/factory behavior but does not revoke/grant microphone permission, start the real Conversation/Walkie services, wait past the foreground deadline, or inspect fatal/ANR output. There is no repeatable fresh-install versus upgrade/preserved-state APK matrix, so a green host suite can still ship another device-only crash loop.

## Desired Improvement
Keep the existing unit/component suite, and add an executable qualification harness for the packaged APK. It should run the real service/permission/lifecycle paths, capture logcat/process-exit evidence, and cover both fresh install and upgrade with persisted state before asking the user to spend another manual installation cycle.

## Value Proposition
Makes the rest of this backlog (and all future work) safe to execute without manual-only verification.

## Acceptance Criteria
- [x] High-risk credential, utility, database, engine, transport, and lifecycle code has a substantive JVM/instrumentation baseline
- [ ] A test installs the actual debug APK fresh, denies microphone, enters/restores each voice mode, waits beyond the foreground deadline, and asserts no fatal/ANR or live orphan service
- [ ] A test grants, revokes, and permanently denies microphone/Nearby permissions across Activity recreation and process relaunch
- [ ] A test upgrades over a build with persisted Conversation and Walkie state, then verifies safe migration/recovery
- [ ] Real Conversation and Walkie services are started, bound, cancelled, backgrounded, foregrounded, and stopped on the API 23/31/34/36 matrix where infrastructure is available
- [ ] The gate archives sanitized logcat, process-exit reason, APK hash, device/API, and test result so one failed install yields actionable evidence
- [ ] The release gate fails automatically on `FATAL EXCEPTION`, `ForegroundServiceDidNotStartInTimeException`, foreground-service ANR, or unexpected process death

## Implementation Notes
Prefer Gradle Managed Devices or scripted emulator lanes for deterministic API coverage, plus the two-phone manual Bluetooth/SCO gate for hardware-specific behavior. This enhancement does not claim that emulator automation replaces the physical Bluetooth check; it reduces how often the human check discovers basic service/permission crashes first.
