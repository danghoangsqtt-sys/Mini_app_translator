# 🔧 ENHANCEMENT: Fix unsynchronized field race in `RecognizerService.languageCode`

## Meta
- **ID**: ENH-009
- **Type**: Enhancement
- **Status**: new
- **Created**: 2026-09-19
- **Breaking**: No

## Summary
`_walkie_talkie_mode/recognizer_services/RecognizerService.java:77-85` spawns a `new Thread("changeLanguage")` purely to assign the non-`volatile` field `languageCode`, later read on the Handler thread (line 64) with no synchronization.

## Current Feature
Language switching in WalkieTalkie mode's recognizer services.

## Current Behavior
A throwaway thread adds no real concurrency benefit but introduces a memory-visibility race on `languageCode`.

## Desired Improvement
Either make `languageCode` `volatile` (simplest fix given the trivial assignment) or perform the assignment directly on the calling thread without spawning a thread at all.

## Value Proposition
Removes a latent race and unnecessary thread churn for a single field write.

## Acceptance Criteria
- [ ] `languageCode` reads/writes are memory-safe across threads
- [ ] No unnecessary thread spawned for a simple field assignment
