# 🐛 BUG: Foreground voice services lack required service types and permissions

## Meta
- **ID**: BUG-015
- **Type**: Bug
- **Status**: in_progress (Phase 3, task 3.5 implemented/static PASS; device QA pending)
- **Severity**: High
- **Created**: 2026-09-20
- **Affected**: `app/src/main/AndroidManifest.xml:18,68-72`, `app/src/main/java/nie/translator/rtranslatordevedition/voice_translation/VoiceTranslationService.java:249`

## Summary
The original audit found foreground services without types. The manifest now declares `microphone|connectedDevice` service types and the matching normal permissions; runtime ordering and Android 14+ behavior still require device validation.

## Actual Behavior
Only `android.permission.FOREGROUND_SERVICE` is declared, and `startForeground(11, notification)` is called without a declared service type.

## Expected Behavior
Declare the precise foreground service types and their matching permissions, then start foreground work only after runtime prerequisites such as `RECORD_AUDIO` and Bluetooth permissions are granted.

## Acceptance Criteria
- [ ] Each foreground service has the minimum correct `android:foregroundServiceType`
- [ ] `FOREGROUND_SERVICE_MICROPHONE` and/or `FOREGROUND_SERVICE_CONNECTED_DEVICE` are declared where required
- [ ] Foreground promotion uses a compatible API that supplies the active type on supported Android versions
- [ ] Starting Conversation and WalkieTalkie modes on Android 14+ does not throw `MissingForegroundServiceTypeException` or `SecurityException`
- [ ] Background-start restrictions and permission ordering are covered by tests or a documented device test matrix

## Fix
Implemented in Phase 3 Cluster A. Keep the request in progress until the required Android 14+ foreground-service and Bluetooth device matrix passes.
