# 🔧 ENHANCEMENT: Pair gRPC `channel.shutdown()` with `awaitTermination`

## Meta
- **ID**: ENH-008
- **Type**: Enhancement
- **Status**: new
- **Created**: 2026-09-19
- **Breaking**: No

## Summary
`Recognizer.java:323-336` (`destroy()`) calls `channel.shutdown()` without `awaitTermination` — explicitly removed per an inline comment at line 330 — so in-flight gRPC resources aren't guaranteed to close before the channel reference is dropped.

## Current Feature
Recognizer teardown when a session ends or is restarted.

## Current Behavior
Fire-and-forget shutdown; possible resource/thread leak under rapid recognizer restarts.

## Desired Improvement
Call `awaitTermination(timeout, unit)` after `shutdown()` (with a bounded timeout so teardown doesn't hang indefinitely), falling back to `shutdownNow()` if it doesn't complete in time.

## Value Proposition
Prevents accumulating leaked gRPC threads/resources during sessions with frequent recognizer restarts (e.g. language switches in WalkieTalkie mode).

## Acceptance Criteria
- [ ] `destroy()` awaits termination with a sane timeout before returning
- [ ] No UI-visible slowdown introduced by the wait (keep timeout short, e.g. 1-2s, with forceful fallback)
