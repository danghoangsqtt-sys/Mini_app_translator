# BUG: Bluetooth transport accepts unbounded inbound payloads and decodes peer images without limits

## Summary

The active `BluetoothCommunicator:1.0.6` dependency reassembles peer-controlled message/data fragments without a byte-count or in-flight-message bound. Mini Conversation then accepts every header `i` payload, decodes the full byte array as a Bitmap on the callback path, and persists it as a Room BLOB without validating compressed size, decoded dimensions, or allocation cost. A paired buggy or malicious peer can therefore drive excessive memory, main-thread decode work, database growth, or process termination.

## Evidence

- `app/build.gradle:121` resolves `com.github.niedev:BluetoothCommunicator:1.0.6` on the release runtime classpath.
- Dependency source `Channel` retains `receivingData`/`receivingMessages` lists and appends fragments until a peer-supplied `FINAL` marker; no total byte/in-flight count is enforced.
- `ConversationBluetoothCommunicator.java:178-197` trusts header `i`, calls `Tools.convertBytesToBitmap(data.getData())`, queues persistence, and updates UI.
- `Tools.java:91-93` calls `BitmapFactory.decodeByteArray()` without an `inJustDecodeBounds`/dimension/byte cap.
- `RecentPeerEntity.userImage` stores the resulting encoded bytes as an unrestricted BLOB; the application also enables `android:largeHeap="true"`, masking rather than bounding memory pressure.

## Acceptance Criteria

- [ ] Enforce protocol limits before or during fragment reassembly: maximum text bytes, image bytes, in-flight message count, fragment count, and timeout.
- [ ] Reject unknown headers and malformed/out-of-order sequences recoverably without retaining partial state indefinitely.
- [ ] Decode images off the main thread after validating encoded length and dimensions; downsample to a fixed pixel/allocation budget.
- [ ] Bound/coalesce persistence work and cap the stored BLOB size.
- [ ] Add adversarial tests for oversized image/text, missing final fragment, many concurrent message IDs, malformed bitmap, and repeated bursts.
- [ ] Verify normal two-phone interoperability and legacy framing remain compatible.
