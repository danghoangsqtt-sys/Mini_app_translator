# BUG: Service binding is recorded before bind success and can crash during unbind

## Summary

Conversation and WalkieTalkie add a `CustomServiceConnection` to their active lists before calling `bindService()`, then ignore the boolean result. Their disconnect paths later call `unbindService()` unconditionally for any listed item. If binding returns `false`, or startup fails between `startService()` and bind completion, Android can throw `IllegalArgumentException: Service not registered` while the Fragment is stopping.

## Resolution

2026-09-28: Activity lists now retain only successful registrations. Each connection owns exact-once release state, contains an already-unregistered teardown, and routes false bind/null binding/binding death through the recoverable callback before removing the registration. Regression tests cover false bind, repeated release, null binding, binding death, and teardown exceptions; existing API 36 mode lifecycle tests pass.

## Re-detected

2026-09-28 deep continuation: `ConversationMainFragment` and `WalkieTalkieFragment` initialize a placeholder communicator with ID `0`, then start an asynchronous service-start/bind sequence. If `onStop()` runs after the bind request starts but before `onServiceConnected()`, disconnect searches by the placeholder ID and cannot find the registered connection (whose ID starts at `1`). The late callback can still retain and call `restoreAttributesFromService()` on the stopped Fragment. The same asynchronous gap exists before the connection object is even created while language lookup/service start is pending. A cancellable connection handle or generation token must be returned at connect initiation, released from `onStop()`, and checked before bind and before callback delivery. Also stop the just-started service if binding fails and no valid client remains. Add deterministic stop-before-connect and stop-before-start-callback tests for both modes.
