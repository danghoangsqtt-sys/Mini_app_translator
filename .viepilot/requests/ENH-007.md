# 🔧 ENHANCEMENT: Guard debug/error logging with `BuildConfig.DEBUG`

## Meta
- **ID**: ENH-007
- **Type**: Enhancement
- **Status**: resolved (Phase 9, Task 9.9; implementation `6ff92b8`)
- **Priority**: High (active release privacy exposure)
- **Created**: 2026-09-19
- **Breaking**: No

## Summary
First-party code logs operational data and optional legacy recognition transcripts. More importantly, the active `BluetoothCommunicator:1.0.6` runtime dependency logs complete sent/received Conversation text, binary data interpreted as text, and remote Bluetooth addresses at error level. These calls remain in the minified release DEX.

## Current Feature
General logging around token refresh and consumption tracking.

## Current Behavior
Every build, including release, can write private Conversation payloads and peer identifiers to Logcat. R8 is enabled for release but the project has no `assumenosideeffects`/logging removal rule, and a built release APK still contains the tags `messageSend`, `clientMessageReceive`, `clientDataReceive`, and `dataSend`.

## Desired Improvement
Remove payload/identifier logging from the Bluetooth transport (upgrade, fork, or vendor a reviewed dependency), sanitize first-party logs, and enforce a release rule/test proving sensitive log calls and their tag strings are absent from the final DEX.

## Value Proposition
Prevents disclosure of the product's core private conversation content and peer identifiers through production Logcat.

## Acceptance Criteria
- [x] Active Bluetooth transport never logs message/data payloads or peer addresses in release builds
- [x] First-party transcript, peer-name, consumption, token, and exception logs are removed or sanitized for release
- [x] R8/release-artifact regression proves sensitive log tags and representative payload markers are absent from DEX
- [x] No loss of debug-build diagnosability

## Implementation Notes

Task 9.9 vendors the reviewed Apache-2.0 transport source, removes payload/address logging, adds release-bytecode verification, and keeps only sanitized debug diagnostics.

## Discussion

Re-detected by vp-audit 2026-09-28: release-reachable logs now include peer unique names in `PairingFragment`/`PeersInfoFragment`, full recognized speech transcripts at error level in the optional legacy Cloud recognizer, consumption values, and token-fetch exception details. Android's official security guidance recommends removing or sanitizing sensitive/non-constant values from production Logcat; R8 rules currently do not strip these calls.

Re-detected by vp-audit 2026-09-28 (deep continuation): the resolved `releaseRuntimeClasspath` contains `BluetoothCommunicator:1.0.6`. Its source logs `message.getText()` on send and receive and appends the remote Bluetooth address; the release APK built with R8 still contains all four transport log tags plus `recognizerResultFinal`. This promotes the issue from general Low logging hygiene to a High, active privacy defect on the default Conversation path.
