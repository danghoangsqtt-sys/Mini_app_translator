# 🔧 ENHANCEMENT: Guard debug/error logging with `BuildConfig.DEBUG`

## Meta
- **ID**: ENH-007
- **Type**: Enhancement
- **Status**: new
- **Created**: 2026-09-19
- **Breaking**: No

## Summary
`Global.java:494` (`Log.d("token", "token fetched")`) and `ConsumptionsDataManager.java:58,61` (`Log.e("consuptionUpdated", ...)`) log operational/usage data at debug/error level unconditionally, including in release builds.

## Current Feature
General logging around token refresh and consumption tracking.

## Current Behavior
Every build, including release, writes these lines to logcat.

## Desired Improvement
Gate non-essential debug logging behind `BuildConfig.DEBUG` (or a dedicated log level), and avoid logging operation names that hint at token lifecycle events even at info level in release builds.

## Value Proposition
Reduces information exposure in release logcat and establishes a discipline that matters more if token-related logging ever expands.

## Acceptance Criteria
- [ ] Flagged log lines gated or removed for release builds
- [ ] No loss of debug-build diagnosability
