# 🔧 ENHANCEMENT: Add app-layer encryption/authentication for Bluetooth conversation payloads

## Meta
- **ID**: ENH-001
- **Type**: Enhancement
- **Status**: new
- **Created**: 2026-09-19
- **Breaking**: Possibly (protocol change between app versions)

## Summary
Incoming connections are gated only by a 15s Yes/No `AlertDialog` (`_conversation_mode/PairingFragment.java:101-125`); message/image payloads (`ConversationBluetoothCommunicator.java:299-321,340-346`) are handed directly to the third-party `com.github.niedev:BluetoothCommunicator:1.0.6` library with no additional app-layer encryption.

## Current Feature
Conversation mode's confidentiality depends entirely on whatever transport security the unaudited third-party Bluetooth library provides.

## Current Behavior
Translated speech text and profile photos are sent as-is to the transport library.

## Desired Improvement
Add app-layer encryption (e.g. per-session symmetric key exchanged during pairing) so confidentiality does not rest solely on an unaudited dependency.

## Value Proposition
This is the app's core feature (private conversation translation) — defense-in-depth here materially reduces risk if the underlying Bluetooth library has undiscovered transport weaknesses.

## Acceptance Criteria
- [ ] Payloads encrypted at the app layer before being handed to the Bluetooth library
- [ ] Backward-compatibility/versioning story for pairing with older app versions (or accept as breaking with a version gate)
- [ ] Existing functionality (connect, message, image transfer) preserved
