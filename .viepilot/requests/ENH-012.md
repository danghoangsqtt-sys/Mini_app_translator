# 🔧 ENHANCEMENT: Refresh dependencies frozen at 2018–2020 versions

## Meta
- **ID**: ENH-012
- **Type**: Enhancement
- **Status**: planned (Phase 3, task 3.3 — see `.viepilot/phases/phase-3-android-modernization/SPEC.md`)
- **Created**: 2026-09-19
- **Breaking**: Possibly (API surface changes in major version bumps)

## Summary
Core dependencies are frozen at old versions: gRPC 1.11.0, `google-auth-library-oauth2-http` 0.8.0, `nimbus-jose-jwt` 5.1, JUnit 4.12, Espresso 3.2.0.

**Re-detected 2026-09-19 (`/vp-audit` Tier 3 re-pass)** — two more outdated deps confirmed directly in `app/build.gradle`, not previously named in this list:
- `androidx.room:room-runtime`/`room-rxjava2`/`room-guava` pinned to `2.1.0` (`app/build.gradle:130-138`) — several major/minor releases behind current stable; bump alongside the `BUG-007` (duplicate DB instance) fix since both touch `AppDatabase`.
- `com.google.android.gms:play-services-nearby:17.0.0` (`app/build.gradle:104`) — the Nearby Connections API surface has moved on since this version; worth checking for behavioral/compatibility changes on Android 13/14 devices even though `BluetoothCommunicator` (not raw Nearby) is the primary P2P transport in this app. Confirm exact current stable version from Maven Central at implementation time rather than trusting any pre-stated number.

## Current Feature
Networking (gRPC), auth (Google OAuth2), JWT parsing, persistence (Room), P2P discovery (Nearby), and test dependencies.

## Current Behavior
Dependencies predate years of security patches and API improvements upstream.

## Desired Improvement
Bump each dependency to a current stable release, reviewing changelogs/CVE advisories for each before upgrading (do not assume specific CVE numbers without checking — this request exists to trigger that review, not to assert known vulnerabilities).

## Value Proposition
Reduces exposure to any vulnerabilities patched upstream since these versions were pinned, and unblocks the toolchain upgrade in ENH-011 (newer AGP/Gradle may require newer dependency versions anyway).

## Acceptance Criteria
- [ ] Each dependency's current stable version reviewed for breaking changes and (where findable) security advisories
- [ ] Dependencies bumped incrementally with build/test verification at each step
- [ ] Sequenced together with or after ENH-011 (toolchain upgrade), since they're likely coupled
