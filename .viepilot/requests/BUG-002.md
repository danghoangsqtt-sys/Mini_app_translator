# 🐛 BUG: Service-account key exposed via unencrypted Android Auto Backup

## Meta
- **ID**: BUG-002
- **Type**: Bug
- **Status**: new
- **Severity**: Critical
- **Created**: 2026-09-19
- **Affected**: `app/src/main/AndroidManifest.xml`, `app/src/main/res/xml/backup_scheme.xml`

## Summary
`AndroidManifest.xml:25-27` sets `android:allowBackup="true"` with `fullBackupContent="@xml/backup_scheme"`, but the backup scheme only excludes an unrelated `AccessTokenLoader.xml` SharedPreferences file (`backup_scheme.xml:19-21`) — it does not exclude `filesDir` (where the service-account key from BUG-001 is stored) or the SharedPreferences key `apiKeyFileName`.

## Actual Behavior
`adb backup` or a cloud backup/restore of the device includes the plaintext GCP service-account key.

## Expected Behavior
`backup_scheme.xml` should explicitly exclude the directory/file holding the service-account key (and any preference key referencing it), or `allowBackup` should be disabled entirely if broader exclusion is impractical.

## Steps to Reproduce
1. Load a GCP key into the app (as in BUG-001).
2. Run `adb backup -f backup.ab nie.translator.rtranslatordevedition` (or trigger a cloud backup).
3. Extract the backup archive — the key file is present.
