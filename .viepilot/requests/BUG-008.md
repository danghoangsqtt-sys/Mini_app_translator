# 🐛 BUG: AES/CTR encryption helpers used without a MAC (malleable ciphertext)

## Meta
- **ID**: BUG-008
- **Type**: Bug
- **Status**: implemented locally; remote persistence pending (Phase 2, task 2.2)
- **Severity**: Medium
- **Created**: 2026-09-19
- **Affected**: legacy `tools/Tools.java` AES/CTR helper API (removed)

## Summary
The former `Tools.encript`/`decript` API used AES/CTR with no MAC/authentication (no HMAC, no GCM), making ciphertext malleable. It also returned `null` after logging crypto failures. Reachability review found no consumer in this fork, so the API has been removed rather than migrated.

## Actual Behavior
Encrypted data protected only by these helpers can be tampered with undetected; crypto exceptions are swallowed rather than surfaced.

## Expected Behavior
Use an authenticated mode (AES/GCM) or add an HMAC over the CTR ciphertext; propagate crypto failures to callers instead of returning `null` silently.

## Steps to Reproduce
1. Locate a call site using `Tools.encript`/`decript` on sensitive data.
2. Flip a bit in the stored ciphertext — decryption "succeeds" with corrupted plaintext instead of failing.

## Error Messages
None surfaced on tamper — that's the issue. Genuine key errors currently only appear in logcat via `printStackTrace()`.

## Environment
- Version: 1.1.2 (branch `master`)
- Phase: 2 — Correctness & Robustness

## Acceptance Criteria
- [x] Confirm actual call sites/sensitivity before changing behavior: live source and all 141 `master` ancestors contain no caller or persisted consumer.
- [x] Remove the unreachable unauthenticated helper API, so no sensitive data can use it and no `null` crypto failure path remains.
- [x] Keep credential persistence on its existing Keystore-backed AES-GCM implementation; no migration is needed for a format this app never wrote.

## Fix
Removed `encript`, `decript`, `decriptToString`, and `CipherData` from `Tools.java`.
The historical reachability scan found no serialized data contract or caller to preserve, so
there is no read-old/write-new migration. A source regression test prevents restoring the
unauthenticated AES/CTR transform. `CredentialStore` remains unchanged and continues to
authenticate credential ciphertext with AES-GCM.
