# 🔧 ENHANCEMENT: Encrypt contact photo BLOB at rest

## Meta
- **ID**: ENH-002
- **Type**: Enhancement
- **Status**: new
- **Created**: 2026-09-19
- **Breaking**: No

## Summary
`database/entities/RecentPeerEntity.java:31-32` stores a contact's profile photo (`userImage`) as an unencrypted BLOB in the Room/SQLite database.

## Current Feature
Recent-peers list with contact photos (`RecentPeersDataManager`).

## Current Behavior
Photo bytes are stored in plaintext in the local SQLite file.

## Desired Improvement
Encrypt the BLOB at rest (e.g. via SQLCipher, or by storing an encrypted file reference instead of the raw BLOB), consistent with the credential-storage hardening in BUG-001.

## Value Proposition
Reduces privacy exposure of a third party's photo if the device is compromised or rooted — modest but real, since this is PII belonging to someone who isn't even the app's own user.

## Acceptance Criteria
- [ ] Photo bytes are not recoverable in plaintext from a raw DB file dump
- [ ] No regression in recent-peers UI (photos still display correctly)
