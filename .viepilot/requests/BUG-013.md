# 🐛 BUG: Missing Android 12+ Bluetooth runtime permissions (blocks safe targetSdk 31+ upgrade)

## Meta
- **ID**: BUG-013
- **Type**: Bug
- **Status**: planned (Phase 3, task 3.2 — see `.viepilot/phases/phase-3-android-modernization/SPEC.md`)
- **Severity**: High
- **Created**: 2026-09-19
- **Affected**: `AndroidManifest.xml:11,13`, `voice_translation/VoiceTranslationActivity.java:81-83`, `VoiceTranslationFragment.java`, `VoiceTranslationService.java`, `api_management/ApiManagementFragment.java`

## Summary
The manifest only declares the legacy `BLUETOOTH` / `BLUETOOTH_ADMIN` permissions, and the runtime permission-request array in `VoiceTranslationActivity.java:81-83` only requests `BLUETOOTH`, `BLUETOOTH_ADMIN`, `ACCESS_COARSE_LOCATION`. There is no reference anywhere in the codebase to `BLUETOOTH_SCAN`, `BLUETOOTH_CONNECT`, or `BLUETOOTH_ADVERTISE` (confirmed via full-project grep — zero matches).

**Important nuance vs. how this is sometimes reported**: because `targetSdkVersion` is currently pinned at 29 (`app/build.gradle:32`), the app runs under Android's legacy Bluetooth permission model on API 31+ devices too — the OS auto-grants Bluetooth access based on the old permissions + location, so Conversation/WalkieTalkie mode does **not** crash today on a stock install. The real trigger is `ENH-011` (now planned for target API 36): the moment `targetSdkVersion` moves to 31 or above, Android stops honoring the legacy permissions for Bluetooth scan/connect calls, and every `BluetoothCommunicator`/`BluetoothAdapter` call in Conversation mode can throw `SecurityException` because the app never declared or requested the new permissions.

## Actual Behavior
No `BLUETOOTH_SCAN` / `BLUETOOTH_CONNECT` / `BLUETOOTH_ADVERTISE` permission declared or requested anywhere.

## Expected Behavior
- Add `<uses-permission android:name="android.permission.BLUETOOTH_SCAN" />`, `BLUETOOTH_CONNECT`, and (if the app advertises/becomes discoverable) `BLUETOOTH_ADVERTISE` to the manifest, each with `android:usesPermissionFlags="neverForLocation"` if location is genuinely not derived from the scan (evaluate case-by-case).
- Add the same three constants to the runtime permission-request array(s) alongside the existing Bluetooth/location requests, gated by `Build.VERSION.SDK_INT >= Build.VERSION_CODES.S`.
- Sequence this as a **hard prerequisite** inside `ENH-011`'s targetSdk bump — do not land the targetSdk 31+ change without this fix in the same PR, or Conversation/WalkieTalkie mode will crash on first Bluetooth use on Android 12+.

## Steps to Reproduce (once targetSdk is bumped to 31+ per ENH-011, without this fix)
1. Bump `targetSdkVersion` to 31 or higher.
2. Install on an Android 12+ device.
3. Start Conversation mode → first Bluetooth scan/connect call throws `SecurityException`, crashing the app.

## Error Messages
`java.lang.SecurityException: Need BLUETOOTH_SCAN permission` (or `BLUETOOTH_CONNECT`), thrown by the platform once targetSdk >= 31.
