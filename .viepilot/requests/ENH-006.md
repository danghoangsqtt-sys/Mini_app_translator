# 🔧 ENHANCEMENT: Stop swallowing exceptions via bare `printStackTrace()`

## Meta
- **ID**: ENH-006
- **Type**: Enhancement
- **Status**: new
- **Created**: 2026-09-19
- **Breaking**: No

## Summary
Multiple locations catch exceptions and only call `printStackTrace()`, silently continuing with no user feedback or retry: `api_management/ApiManagementFragment.java:208,222`, `settings/SettingsFragment.java:244,257`, `GeneralService.java:66-68` (all `RemoteException`), plus the crypto error paths already tracked in BUG-008.

## Current Feature
Various `RemoteException` handling around service binding/IPC.

## Current Behavior
Failures are invisible to the user and to any monitoring — stack traces only reach logcat, which is stripped or ignored in release builds.

## Desired Improvement
Replace bare `printStackTrace()`-only catches with at minimum a logged warning plus, where the UX expects a result, a visible failure/retry state for the user.

## Value Proposition
Turns silent failures into diagnosable, user-visible ones — meaningfully improves debuggability of field reports.

## Acceptance Criteria
- [ ] Each flagged catch block either surfaces the failure to the user or logs it at an appropriate level with context
- [ ] No new crashes introduced by now-visible failure paths
