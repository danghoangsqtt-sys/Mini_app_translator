# 🔧 ENHANCEMENT: Replace swallowed errors and add privacy-safe field diagnostics

## Meta
- **ID**: ENH-006
- **Type**: Enhancement
- **Status**: resolved (Phase 9, Task 9.13; `489e569`, persisted)
- **Priority**: Medium
- **Created**: 2026-09-19
- **Breaking**: No

## Summary
Multiple locations catch exceptions and only call `printStackTrace()`, silently continuing with no user feedback or retry: `api_management/ApiManagementFragment.java:208,222`, `settings/SettingsFragment.java:244,257`, `GeneralService.java:66-68` (all `RemoteException`), plus the crypto error paths already tracked in BUG-008.

## Current Feature
Various `RemoteException` handling around service binding/IPC.

## Current Behavior
Failures are invisible to the user and to any monitoring — stack traces only reach logcat, which is stripped or ignored in release builds.

## Desired Improvement
Replace bare `printStackTrace()`-only catches with at minimum a logged warning plus, where the UX expects a result, a visible failure/retry state for the user.

## Value Proposition
Turns silent failures into diagnosable, user-visible ones — meaningfully improves debuggability of field reports.

## Acceptance Criteria
- [ ] Each flagged catch block either surfaces the failure to the user or logs it at an appropriate level with context
- [ ] No new crashes introduced by now-visible failure paths
- [ ] API 30+ records a small, privacy-safe process-state breadcrumb and reads `ApplicationExitInfo` after relaunch to distinguish crash, ANR, low-memory, permission, and user-stop exits
- [ ] The app exposes a user-initiated diagnostic export containing build/version, Android/API/device class, permission states, selected mode, sanitized service milestones, and the last process-exit reason
- [ ] Diagnostic output excludes recognized/translated text, peer names/addresses, credentials, model contents, audio, and stable advertising identifiers
- [ ] Foreground-service start/promotion failures retain a sanitized exception category and lifecycle stage instead of collapsing to an invisible generic error

## Implementation Notes

- Local implementation `489e569` adds an enum-only, process-wide diagnostics boundary with a 16-event ring, saturated counters, and an API 30+ process summary capped at 128 bytes.
- `ApplicationExitInfo` is reduced to mapped reason/status/importance/timestamp and the validated compact summary; descriptions, traces, process names, memory samples, identifiers, and exception text are never read.
- Settings exports a fixed-schema report of at most 8 KiB through `ACTION_CREATE_DOCUMENT`; it requests no storage permission and performs no upload or telemetry.
- Scoped IPC, service-start/bind, permission, and foreground-promotion failures emit sanitized categories. Same-process Messenger round trips were replaced with direct Handler dispatch.
- Gates pass: 201 JVM tests, 26 API 36 instrumentation tests, lint 0 errors/122 warnings, debug/release assembly, R8 privacy verification, clean diff, and verified remote persistence.

## Discussion

Re-detected by vp-audit 2026-09-29 after repeated physical-install failures. The current project has no `ApplicationExitInfo`, `setProcessStateSummary`, uncaught-exception, or structured last-run diagnostic path. `VoiceTranslationService.promoteToForeground()` catches `RuntimeException` and emits a generic error before a client is guaranteed to be bound; multiple IPC catches still only call `printStackTrace()`. As a result, a tester must reproduce with live ADB/logcat or reinstall repeatedly, and the precise exit class is lost after relaunch.

Android 11/API 30 provides `ActivityManager.getHistoricalProcessExitReasons()` and `ApplicationExitInfo` specifically for recent process-death diagnosis. Any state summary must remain small and contain no sensitive data.

Reference: https://developer.android.com/reference/android/app/ApplicationExitInfo and https://developer.android.com/reference/android/app/ActivityManager#getHistoricalProcessExitReasons(java.lang.String,%20int,%20int)

## Planning

Task 9.13 adds a local-only diagnostics boundary, API 30+ process-exit mapping, sanitized service/IPC error categories, and a user-triggered SAF text export. It explicitly forbids telemetry, raw traces, payloads, peer identifiers, credentials, audio, and new permissions.
