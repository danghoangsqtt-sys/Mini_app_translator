# 🐛 BUG: Unrestricted Downloads `.json` scan + legacy storage model

## Meta
- **ID**: BUG-006
- **Type**: Bug
- **Status**: resolved (Phase 1, task 1.6)
- **Severity**: High
- **Created**: 2026-09-19
- **Affected**: `api_management/KeyFileContainer.java:94,137-154`, `AndroidManifest.xml:19-20,30`

## Summary
The key-file picker recursively scans the entire public Downloads directory for any `*.json` file, combined with `requestLegacyExternalStorage="true"` and broad `WRITE_EXTERNAL_STORAGE`/`READ_EXTERNAL_STORAGE` permissions — the deprecated legacy storage model with a wide attack/confusion surface.

## Actual Behavior
Any `.json` file in Downloads matches, with no filename/schema precision, and the app opts out of scoped storage.

## Expected Behavior
Use the Storage Access Framework (`ACTION_OPEN_DOCUMENT`) to let the user pick a specific file, drop `requestLegacyExternalStorage` and the broad storage permissions, and (ideally) validate the selected file actually looks like a GCP service-account key before accepting it.

## Steps to Reproduce
1. Place multiple unrelated `.json` files in `Downloads/`.
2. Open the key-file picker in the app — all of them are offered as candidates with no differentiation.

## Error Messages
N/A — a usability/security design issue, not a crash.

## Environment
- Version: 1.1.2 (branch `master`)
- Phase: 1 — Security & Stability Hardening

## Acceptance Criteria
- [x] Key selection uses SAF (`ACTION_OPEN_DOCUMENT`) instead of a manual directory scan
- [x] `requestLegacyExternalStorage` and broad storage permissions removed once SAF migration lands
- [x] Basic validation that the selected file is a plausible service-account key before accepting it

## Fix

- Replaced recursive Downloads traversal with an `ACTION_OPEN_DOCUMENT` JSON picker and content-URI import.
- Removed direct legacy-storage configuration and the transitive `READ_EXTERNAL_STORAGE` manifest declaration.
- Added bounded, pre-encryption service-account validation plus JVM/manifest regression tests.
- Verified on the API 36 `medium_phone` emulator: picker open/cancel, invalid rejection, valid import persistence across relaunch, and gallery-provider entry without a storage permission prompt.
