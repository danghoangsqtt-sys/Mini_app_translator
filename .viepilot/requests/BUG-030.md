# BUG: Recent-peer ID and profile-image persistence has a write/read race

## Summary

The Bluetooth handshake persists a peer ID on an unmanaged `Thread`, then handles the following image frame by launching a separate `AsyncTask` query and updating only peers returned by that query. Because those operations are not serialized or transactional, the image query can win the race, find no newly inserted peer, and silently drop the received profile image. The declared `cachedRecentPeers` list is never assigned, so it does not close this ordering gap.

## Resolution

2026-09-28: all recent-peer Room work now uses one serial executor; the ID upsert is queued before handshake replies, image/name updates address the peer directly, the unused cache and AsyncTasks were removed, and read callbacks return main-dispatched defensive list snapshots. A deterministic manual-executor test queues image update before identity insert completion and confirms the final row retains the image.

## Re-detected

2026-09-28 deep continuation: `Executors.newSingleThreadExecutor()` serializes operations but uses an unbounded `LinkedBlockingQueue`; it does not satisfy this request's explicit "bounded executor or Room transaction/upsert" criterion. Bluetooth callbacks can enqueue identity, image, and name writes without backpressure, while write paths do not contain/report Room runtime failures. Under a noisy or malicious peer this can create unbounded retained work, silent persistence loss, and memory pressure. Keep the deterministic ordering fix, but add a bounded/coalescing queue or transactional repository boundary, define rejection/failure behavior, and test burst load plus database exceptions.

## Final resolution

Task 9.12 implementation `484e67f` replaces the unbounded queue with a keyed serial executor capped at 32 pending tasks plus one running task and a backing queue capped at one. Same-key writes coalesce in place; queue overflow, shutdown, and Room failures emit sanitized operation/reason enums on the callback executor and do not terminate later work. Deterministic tests cover burst coalescing, ordering, overflow, defensive copies, Room exceptions, observer exceptions, shutdown, and post-close rejection.
