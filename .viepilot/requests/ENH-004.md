# 🔧 ENHANCEMENT: Fix `FileLog` hardcoded legacy path and unclosed resource

## Meta
- **ID**: ENH-004
- **Type**: Enhancement
- **Status**: new
- **Created**: 2026-09-19
- **Breaking**: No

## Summary
`tools/FileLog.java:29` uses a hardcoded legacy path `"sdcard/log.txt"` (pre-scoped-storage API, will fail under modern storage restrictions), and `buf.close()` at line 42 is not in a `finally`, leaking the `BufferedWriter`/`FileWriter` if `append`/`newLine` throws.

## Current Feature
Ad-hoc file logging utility.

## Current Behavior
Hardcoded path bypasses scoped storage; writer can leak on exception.

## Desired Improvement
Use `Context.getExternalFilesDir()`/`getFilesDir()` for a proper app-scoped log path, and wrap the writer in try-with-resources.

## Value Proposition
Prevents a logging utility from silently failing (or leaking file handles) on modern Android versions once BUG-006's storage migration lands.

## Acceptance Criteria
- [ ] Log path uses a scoped-storage-compliant location
- [ ] Writer resource always closed (try-with-resources or finally)
