# 🐛 BUG: `WalkieTalkieService.onDestroy` unconditional `unbindService` crash risk

## Meta
- **ID**: BUG-010
- **Type**: Bug
- **Status**: new
- **Severity**: Medium
- **Created**: 2026-09-19
- **Affected**: `voice_translation/_walkie_talkie_mode/_walkie_talkie/WalkieTalkieService.java:264-272` (`onDestroy`), 247-255 (`onStartCommand`)

## Summary
`onDestroy()` unconditionally calls `unbindService(firstLanguageConnection)` / `unbindService(secondLanguageConnection)`, but binding only happens conditionally inside `onStartCommand` (only on "first launch").

## Actual Behavior
If the service is destroyed before that conditional bind branch ever executes (e.g. killed/restarted by the system before `onStartCommand` runs), `unbindService` throws `IllegalArgumentException: Service not registered`.

## Expected Behavior
Track whether each connection was actually bound (a boolean flag per connection) and only unbind if it was.

## Steps to Reproduce
1. Cause the system to kill `WalkieTalkieService` before `onStartCommand`'s bind branch runs (e.g. low-memory kill immediately after service creation).
2. Service restart triggers `onDestroy` without a prior successful bind → crash.

## Error Messages
`java.lang.IllegalArgumentException: Service not registered: ...`

## Environment
- Version: 1.1.2 (branch `master`)
- Phase: 2 — Correctness & Robustness

## Acceptance Criteria
- [ ] `onDestroy` only unbinds connections that were actually bound
- [ ] Test or manual verification of the low-memory-kill-before-bind path no longer crashes
