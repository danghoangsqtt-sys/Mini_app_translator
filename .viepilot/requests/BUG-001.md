# 🐛 BUG: Google Cloud service-account key stored unencrypted at rest

## Meta
- **ID**: BUG-001
- **Type**: Bug
- **Status**: resolved (Phase 1, task 1.1)
- **Severity**: Critical
- **Created**: 2026-09-19
- **Affected**: `api_management/KeyFileContainer.java`, `Global.java`

## Summary
The user-selected Google Cloud service-account JSON key (scope `cloud-platform`) is copied verbatim into app-private storage and read back with plain `FileInputStream` — no encryption at rest.

## Actual Behavior
`KeyFileContainer.java:168` copies the file with `Tools.copyFile(file, new File(activity.getFilesDir(), file.getName()))`. `Global.java:497` (`GetApiTokenRunnable.run`) reads it back via plain `FileInputStream` and calls `GoogleCredentials.fromStream(...).createScoped(SCOPE)` with the full `cloud-platform` scope (`Global.java:51,499`).

## Expected Behavior
The key should be stored via `EncryptedFile`/Android Keystore-backed encryption so that reading app-private storage directly (root, backup extraction, another local exploit) does not yield a usable credential.

## Steps to Reproduce
1. Complete onboarding and load a GCP service-account key file into the app.
2. Inspect `/data/data/nie.translator.rtranslatordevedition/files/` (root or `adb backup`) — the key file is present in plaintext JSON.

## Error Messages
N/A — this is a data-at-rest exposure, not a crash.

## Environment
- Version: 1.1.2 (branch `master`, stale lineage — see ENH-015)
- Phase: 1 — Security & Stability Hardening

## Acceptance Criteria
- [x] Key file is encrypted at rest with Android Keystore-backed AES-GCM
- [x] Root cause identified and documented in the fix commit
- [x] Regression test confirms the on-disk file is not raw-readable JSON

## Fix

Introduced `CredentialStore` as the single persistence boundary for the service-account JSON. It encrypts credentials with AES-GCM using a non-exportable Android Keystore key, validates a bounded/versioned envelope, migrates the legacy plaintext file only after the encrypted replacement is durable, and removes stored data plus its key on deletion. Token refresh now consumes a decrypted in-memory stream whose buffer is wiped when closed.

Verification on 2026-09-20: application source, Android test source, unit tests, lint, and debug APK build passed. The Android Keystore instrumentation suite compiled; runtime execution awaits a connected API 23+ device/emulator at the Phase 1 exit gate.
