# 🐛 BUG: Google Cloud service-account key stored unencrypted at rest

## Meta
- **ID**: BUG-001
- **Type**: Bug
- **Status**: in progress (Phase 1, task 1.1)
- **Severity**: Critical
- **Created**: 2026-09-19
- **Affected**: `api_management/KeyFileContainer.java`, `Global.java`

## Summary
The user-selected Google Cloud service-account JSON key (scope `cloud-platform`) is copied verbatim into app-private storage and read back with plain `FileInputStream` — no encryption at rest.

## Actual Behavior
`KeyFileContainer.java:168` copies the file with `Tools.copyFile(file, new File(activity.getFilesDir(), file.getName()))`. `Global.java:497` (`GetApiTokenRunnable.run`) reads it back via plain `FileInputStream` and calls `GoogleCredentials.fromStream(...).createScoped(SCOPE)` with the full `cloud-platform` scope (`Global.java:51,499`).

## Expected Behavior
The key should be stored via `EncryptedFile`/Android Keystore-backed encryption so that reading app-private storage directly (root, backup extraction, another local exploit) does not yield a usable credential.

## Steps to Reproduce
1. Complete onboarding and load a GCP service-account key file into the app.
2. Inspect `/data/data/nie.translator.rtranslatordevedition/files/` (root or `adb backup`) — the key file is present in plaintext JSON.
