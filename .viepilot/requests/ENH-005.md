# 🔧 ENHANCEMENT: Replace deprecated `AsyncTask` / no-Looper `Handler()` usage

## Meta
- **ID**: ENH-005
- **Type**: Enhancement
- **Status**: new
- **Created**: 2026-09-19
- **Breaking**: No

## Summary
`AsyncTask` (deprecated since API 30, no cancellation on destroy) is still used in `VoiceTranslationService.java:149-165` (`StartVoiceRecorderTask`) and `RecentPeersDataManager.java:104,154,209`. The deprecated no-`Looper` `Handler()` constructor is used in `ConversationService.java:57`, `_conversation/main/ConversationMainFragment.java:37`, `_walkie_talkie/WalkieTalkieFragment.java:68`.

## Current Feature
Background task execution and delayed UI callbacks across voice translation services/fragments.

## Current Behavior
Uses deprecated APIs with known pitfalls (no auto-cancellation on lifecycle destroy for AsyncTask; ambiguous Looper for bare `Handler()`).

## Desired Improvement
Migrate to `ExecutorService`/`Handler(Looper.getMainLooper())`, cancelling background work in the appropriate lifecycle callback (`onDestroy`).

## Value Proposition
Removes lint warnings, reduces leak risk from tasks/handlers outliving their owning component, and future-proofs against `AsyncTask` removal.

## Acceptance Criteria
- [ ] All flagged `AsyncTask` usages replaced
- [ ] All bare `Handler()` constructors specify a `Looper` explicitly
- [ ] No behavior regression in affected services/fragments
