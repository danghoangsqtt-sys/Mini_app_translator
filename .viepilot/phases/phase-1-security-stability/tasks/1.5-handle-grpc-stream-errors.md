## File-Level Plan

| File | Change | Why |
|---|---|---|
| `Recognizer.java` | Wire `onError`, reset request/queue/recognizing state, suppress teardown errors after completion/destroy, and pass mapped error codes through `RecognizerListener`. | Restore service/UI feedback and make stream teardown idempotent. |
| `RecognizerStreamErrorHandler.java` | Add a terminal-event gate and map gRPC status codes to existing app error reasons. | Keep one error notification per active stream and make mapping testable. |
| `RecognizerStreamErrorHandlerTest.java` | Simulate network, authentication, and internal stream failures plus duplicate terminal events. | Prove callbacks fire once with the expected user-facing reason. |
| ViePilot state/request/changelog | Record start, evidence, status, and completed behavior. | Preserve incremental execution traceability. |

## Defined Service/UI Behavior

- `UNAVAILABLE` and `DEADLINE_EXCEEDED` become `MISSED_CONNECTION`.
- `UNAUTHENTICATED` and `PERMISSION_DENIED` become `WRONG_API_KEY`.
- Other stream failures become the generic `ERROR` reason.
- The existing `RecognizerListener -> VoiceTranslationService/RecognizerService -> client callback` route surfaces the error and ends the current listen session. No automatic retry is attempted with an invalid credential or unknown failure.
