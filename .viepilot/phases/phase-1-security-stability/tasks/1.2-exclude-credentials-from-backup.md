# Task 1.2 — Exclude credentials from Android backup

## Objective

Prevent Android Auto Backup and device transfer from exporting the encrypted credential envelope, a pre-migration plaintext credential, or the preference that records the imported credential name.

## File-Level Plan

| File | Change | Why |
|---|---|---|
| `backup_scheme.xml` | Exclude the entire app-private files domain and the default SharedPreferences file while retaining the existing token preference exclusion. | Covers the fixed encrypted filename and every dynamic legacy plaintext filename before migration. Android backup XML excludes preference files, not individual keys, so the default preference file is the smallest safe boundary for `apiKeyFileName`. |
| `BackupSchemeTest.java` | Parse the production XML and assert all security exclusions are present. | Provides a host-side regression that can run without an Android device. |
| ViePilot state/request/changelog | Record start, evidence, status, and completed behavior. | Preserve incremental execution traceability. |

## Implementation Notes

- Keep `android:allowBackup="true"` so non-sensitive databases and explicitly allowed preferences retain existing backup behavior.
- Exclude `domain="file" path="."` because the former plaintext filename is user-controlled and cannot be enumerated safely.
- Exclude `nie.translator.rtranslatordevedition_preferences.xml` because Android's backup schema cannot exclude a single preference key.
- The project compiles against API 29. Android 12 `dataExtractionRules` will be added with the planned API 36 toolchain upgrade; until then, `fullBackupContent` remains the compatible rule source.
