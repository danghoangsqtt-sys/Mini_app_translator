## File-Level Plan

| File | Change | Why |
|---|---|---|
| `AndroidManifest.xml` | Remove read/write external-storage permissions and `requestLegacyExternalStorage`. | SAF grants access only to the user-selected document. |
| `ApiManagementFragment.java` | Remove storage-permission prompting and route activity results to the key container. | The document picker needs no runtime storage permission. |
| `KeyFileContainer.java` | Launch `ACTION_OPEN_DOCUMENT`, read the selected `content://` URI, resolve display metadata, and report invalid content distinctly. | Eliminate broad directory discovery and accept only an explicit selection. |
| `CredentialStore.java` | Add bounded stream import and validate bytes before encryption. | Avoid creating an intermediate plaintext file and centralize acceptance. |
| `ServiceAccountCredentialValidator.java` | Check UTF-8 JSON shape plus the required service-account fields and private-key marker. | Reject unrelated JSON before persistence. |
| `ServiceAccountCredentialValidatorTest.java` | Cover a plausible service account, unrelated JSON, missing fields, and malformed input. | Provide device-independent validation regression coverage. |
| `StorageAccessManifestTest.java` | Parse the manifest and assert that legacy storage permissions and opt-out are absent. | Keep the wide-storage fix from regressing without needing a device. |

## Implementation Notes

- Keep the existing Fragment result API because this AndroidX/Gradle generation predates the Activity Result API; call `startActivityForResult` only from the owning fragment and forward its result to `KeyFileContainer`.
- Use `ACTION_OPEN_DOCUMENT`, `CATEGORY_OPENABLE`, JSON MIME filtering, and temporary read access. The credential is imported immediately into app-private encrypted storage, so no persistable URI permission is required.
- Do not derive an on-device path from the selected `content://` URI. Resolve only display metadata for the UI, use a bounded `InputStream`, and never log the URI, display name, or credential content on failure.
- Validate a strict flat JSON service-account object before encryption: required non-empty fields, `type=service_account`, and PEM private-key begin/end markers. Keep this validator Android-free so its regressions run in local JVM tests.
- Preserve the established `CredentialStore` AES-GCM/Android Keystore envelope and its plaintext-wiping behavior; import validation must happen before `writeEncrypted` and failure must not change the stored credential name/token state.
- Run the defined Gradle checks. Existing project-wide lint findings not introduced by this task are recorded separately in Phase 3 task 3.6; this task must add no new lint errors.
