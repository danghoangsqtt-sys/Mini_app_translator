# Task 1.1 — Protect stored GCP service-account credentials

## Objective

Replace plaintext credential persistence with an Android Keystore-backed AES-GCM store. Existing users must be migrated without losing a valid key, and no raw service-account JSON may remain in app-private files after successful migration.

## File-Level Plan

| File | Change | Why |
|---|---|---|
| `CredentialStore.java` | Add the single credential persistence boundary using Android Keystore AES-GCM, a versioned binary envelope, bounded reads, authenticated associated data, temporary-file replacement, migration, and secure logical deletion. | Prevent raw JSON from being readable at rest and keep key access in one place. |
| `KeyFileContainer.java` | Import/delete through `CredentialStore`; retain only the source file name as UI metadata. | Stop copying the selected JSON verbatim into app storage. |
| `Global.java` | Read credentials only through the store and lazily migrate the old plaintext file on the token worker thread. | Remove the second plaintext reader while preserving upgrades. |
| `CredentialStoreInstrumentedTest.java` | Verify encrypted round-trip, ciphertext does not contain JSON markers, migration deletes plaintext, and delete removes encrypted state. | Cover the reported exposure on a real Android Keystore provider. |
| ViePilot state/request/changelog | Record start, evidence, status, and completed behavior. | Preserve incremental execution traceability. |

## Implementation Notes

- Minimum SDK is 23, so use `KeyGenParameterSpec`, `KeyProperties`, and AES/GCM/NoPadding without compatibility fallbacks to insecure algorithms.
- Keep the Keystore key non-exportable and usable without interactive authentication because background token refresh must continue to work.
- Authenticate the application package name as AES-GCM associated data.
- Reject malformed envelopes and oversized input before allocation/decryption.
- Only delete a legacy plaintext file after the encrypted replacement is fully written.
- Do not log credential bytes, parsed JSON, private keys, tokens, or source paths.
- Preserve `applicationId`, preference key, and displayed source filename for upgrade compatibility.
