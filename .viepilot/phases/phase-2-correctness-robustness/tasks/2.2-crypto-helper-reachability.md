# Task 2.2 — Resolve unauthenticated crypto helpers

## Request

`BUG-008`

## Objective

Remove the unreachable AES/CTR helper API from `Tools` after proving that neither the
current `master` source tree nor its 141-commit history contains a caller or serialized
consumer. This eliminates malleable encryption without inventing an unnecessary
on-device data migration. `CredentialStore` is already an independent AES-GCM design and
is inspection-only for this task.

## Plan

Search all Java, XML, serialized formats, and historical callers of `Tools.encript/decript`.
The current source tree and all 141 commits reachable from `master` show only helper
definitions, with no caller or persisted-data consumer. Remove the dead CTR helpers and
their `CipherData` dependency. Do not conflate these helpers with `CredentialStore`, which
already uses Keystore-backed AES-GCM.

## File-Level Plan

| File | Change | Why |
|---|---|---|
| `tools/Tools.java` | Remove `encript`, `decript`, `decriptToString`, nested `CipherData`, and imports used only by that unauthenticated CTR implementation. | The APIs have no caller or persisted consumer, so deletion removes the malleable cipher and its null-return failure path without an invented compatibility format. |
| `tools/UnauthenticatedCryptoHelperSourceTest.java` | Add a JVM source regression that asserts `Tools.java` has no CTR transform, `CipherData`, or legacy helper declaration. | Prevents a future reintroduction of unauthenticated encryption while leaving the unrelated credential AES-GCM implementation intact. |
| `BUG-008.md` | Record the evidence, disposition, and why no migration is needed. | The original ticket must not claim an active persisted-data risk after reachability disproves it. |
| Task/phase/tracker/handoff/changelog records | Mark Task 2.2 in progress, then log verification and outcome. | Preserves a recoverable execution trail without altering unrelated worktree changes. |

## Implementation Notes

- Reachability evidence: a live source scan finds definitions only; a scan of all 141 commits reachable from `master`, excluding `Tools.java` itself, finds zero callers or data-format references. The upstream v3 ref is a different package lineage and is not a consumer of this fork's runtime data.
- Keep `CredentialStore` unchanged: it already writes versioned Keystore-backed AES-GCM records and does not import `Tools` crypto helpers.
- Retain unrelated key-generation helpers and `SecureRandom`; they are outside this defect and the secure random generator is used by Bluetooth-name generation.
- Do not add a migration, fallback, or AES-GCM replacement for a format this app never writes. If a future persisted consumer is introduced, it must use authenticated encryption and an explicit format/version contract.
