## Plan

For each recognizer `ServiceConnection`, track at most one active `bindService` registration,
not a successful connection callback or `bindService` return value. Android's
`Context.bindService` reference still requires cleanup when the bind call returns `false`.
Repeated starts while that connection is active must not make a duplicate bind; teardown consumes
and unbinds the one tracked registration.

`onDestroy` must separately attempt communication shutdown, each tracked unbind, and
`super.onDestroy`, logging cleanup exceptions but never using `IllegalArgumentException` as the
binding-state decision. The nearby `onStartCommand(null)` dereference is documented as a separate
follow-up because it is not a binding-lifecycle repair.

## File-Level Plan

| `WalkieTalkieService.java` | Record a registration before invoking `bindService` only when its connection is inactive; release it once during teardown. | Matches Android's dispatcher behavior without treating return value or callback delivery as registration state. |

| `CHANGELOG.md` | Add the lifecycle cleanup fix under Unreleased. | Makes the behavior change traceable. |
