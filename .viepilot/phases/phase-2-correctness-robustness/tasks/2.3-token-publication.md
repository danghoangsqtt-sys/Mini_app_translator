## Plan

Move token ownership into a package-private Java coordinator with one lock. `Global` supplies
credential I/O on a worker thread and an Android `Handler` adapter that schedules only the
coordinator's refresh runnable. The coordinator increments a generation on reset; a late
refresh from an earlier generation cannot publish its token or notify a newer request.

## Synchronization Policy

- The coordinator lock protects the token, pending listener queue, in-flight marker, generation, and scheduled refresh reference.
- Fetching credentials happens through an injected worker executor with no lock held.
- Completion publishes a token only when its captured generation still matches the current generation.
- Listener queues are copied while locked and invoked after the lock is released. Reset gives pending listeners one explicit failure and invalidates prior fetches.
- The scheduler removes only the runnable stored by the coordinator; it never clears a shared handler queue.

## Done when

- No unsynchronized `apiToken` publication or stale refresh callback can overwrite a newer token.
- Each listener receives one terminal result; no deadlock or main-thread network call occurs.
- Concurrency regression and host build checks pass.
