## Source

Phase 3 Cluster A and Phase 5 code pass static checks, but the project lacks the physical-device evidence needed before risky dependency upgrades.

## Plan

Create a device matrix for API 23, 31, 34 and 36. Use two physical phones for Conversation Bluetooth pairing and SCO/headset behavior; use emulators only for cases that do not require real Bluetooth. Exercise first launch, Nearby permission grant/deny/revoke/re-grant, microphone permission, foreground-service transitions, credential picker valid/invalid/cancel paths, Conversation, WalkieTalkie, TTS, background/foreground, screen lock, restart and process recreation. Record device model, OS/API, build commit, result, logs and limitations. Do not mark untested cells as pass.

## Done when

- `DEVICE-MATRIX.md` contains reproducible evidence for every required API/path or an explicit release blocker.
- The two-phone Bluetooth/SCO happy path passes on the baseline commit.
- Permission denial/revocation fails safely without a crash or unauthorized Bluetooth initialization.
- The baseline is tagged or otherwise recorded so dependency-refresh regressions can be compared accurately.
