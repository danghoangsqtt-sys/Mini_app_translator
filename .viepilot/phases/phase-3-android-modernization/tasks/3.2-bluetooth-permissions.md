## Plan

The app uses Google Play services Nearby Connections, not only platform Bluetooth APIs: the actual flow calls `startAdvertising()`, `startDiscovery()`, `connect`, `acceptConnection`, and `disconnect`. `BLUETOOTH_ADVERTISE`, `BLUETOOTH_SCAN`, `BLUETOOTH_CONNECT`, and Android 13+ `NEARBY_WIFI_DEVICES` are therefore in scope. Build a per-API matrix for legacy location/Wi-Fi/Bluetooth declarations and API 31+ Nearby-device runtime grants; grant, deny, and revoke behavior must be handled before advertising, discovery, or connection.

The codebase has no location feature beyond discovery permissions. Evaluate `neverForLocation` from official documentation and observed device behavior, including the filtered-beacon consequence, rather than making it a user-preference decision. Preserve the API 23–30 path and keep this change coupled to 3.1.

## Done when

- No Bluetooth or Nearby `SecurityException` on API 31/34/36 with target API 36 for advertising, discovery, connect, accept, or disconnect.
- Grant/deny/revoke paths, API 23 legacy location/Wi-Fi/Bluetooth behavior, and `neverForLocation` device behavior are tested.
- Two-phone Conversation and one-phone WalkieTalkie smoke tests pass.
